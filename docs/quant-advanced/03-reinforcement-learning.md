# Reinforcement Learning — 강화학습

## 1. 한 줄 요약

**Reinforcement Learning, RL(강화학습)**은 에이전트가 환경과 상호작용하면서 보상을 최대화하는 행동을 학습하는 머신러닝 방식입니다.

트레이딩에서는 에이전트가 다음 행동을 학습합니다.

```text
매수할까?
매도할까?
보유할까?
청산할까?
포지션 크기를 키울까 줄일까?
```

## 2. 기본 구조

강화학습은 보통 다음 구성요소로 설명합니다.

### 2.1 Agent

의사결정을 하는 주체입니다.

트레이딩에서는 자동매매 모델이 agent입니다.

### 2.2 Environment

Agent가 상호작용하는 세계입니다.

트레이딩에서는 시장, 가격 데이터, 주문 체결 환경, 계좌 상태가 environment입니다.

### 2.3 State

현재 상황을 나타내는 정보입니다.

예:

```text
현재 가격
최근 수익률
이동평균선 기울기
볼린저밴드 폭
현재 포지션
미실현 손익
잔고
변동성
거래량
```

### 2.4 Action

Agent가 선택할 수 있는 행동입니다.

예:

```text
0 = HOLD
1 = LONG 진입
2 = SHORT 진입
3 = CLOSE
4 = 포지션 25%
5 = 포지션 50%
```

### 2.5 Reward

행동의 결과로 받는 보상입니다.

트레이딩에서는 보통 수익률을 reward로 쓰지만, 단순 수익률만 쓰면 위험한 모델이 됩니다.

더 좋은 reward:

```text
reward = PnL - 수수료 - 슬리피지 - drawdown penalty - turnover penalty
```

## 3. 왜 트레이딩 RL이 어려운가

트레이딩은 RL을 적용하기 매우 어려운 분야입니다.

### 3.1 시장은 고정된 게임이 아님

바둑이나 게임은 규칙이 고정되어 있습니다. 하지만 시장은 계속 변합니다.

- 참여자가 변함
- 변동성이 변함
- 유동성이 변함
- macro 환경이 변함
- 거래소 구조가 변함

이를 non-stationary environment라고 합니다.

### 3.2 보상이 희소하고 노이즈가 많음

좋은 의사결정을 했는데도 단기적으로 손실이 날 수 있습니다. 반대로 나쁜 의사결정을 했는데 운 좋게 수익이 날 수도 있습니다.

이 때문에 RL 모델이 잘못된 패턴을 학습하기 쉽습니다.

### 3.3 과최적화 위험

과거 데이터에서만 잘 작동하는 agent가 만들어지기 쉽습니다.

실전에서는 다음 문제가 자주 생깁니다.

- 거래 횟수 과다
- 수수료 무시
- 미래 데이터 누수
- unrealistically perfect fill
- 특정 구간에만 맞춘 정책

### 3.4 Exploration 비용

강화학습은 새로운 행동을 시도해보며 배웁니다. 하지만 실전 시장에서 exploration은 실제 돈을 잃는 행위입니다.

따라서 실전 적용 전에는 매우 정교한 시뮬레이터가 필요합니다.

## 4. 트레이딩에서 가능한 적용 방식

### 4.1 직접 매수/매도 정책 학습

Agent가 직접 매매 신호를 냅니다.

```text
state → neural network → action
```

하지만 이 방식은 가장 어렵고 위험합니다.

### 4.2 Position Sizing 학습

진입 신호는 기존 룰 전략이 만들고, RL은 포지션 크기만 결정합니다.

예:

```text
7일선 돌파 신호 발생
RL agent가 현재 시장 상태를 보고 size_pct 결정
```

이 방식이 더 현실적입니다.

### 4.3 Exit Policy 학습

진입은 룰 기반으로 하고, 청산만 RL이 담당합니다.

예:

```text
계속 보유
부분익절
전량청산
손절 앞당김
```

### 4.4 Strategy Allocation

여러 전략 중 어떤 전략에 자본을 배분할지 학습합니다.

```text
현재 시장은 추세장 → trend strategy 비중 증가
현재 시장은 횡보장 → mean reversion 비중 증가
```

## 5. 현재 봇에 적용한다면

현재 단계에서 RL을 바로 매수/매도에 쓰는 것은 추천하지 않습니다.

더 현실적인 적용 순서:

1. 룰 기반 전략 안정화
2. 백테스트 결과와 신호별 feature 저장
3. meta-labeling으로 좋은 신호/나쁜 신호 분류
4. position sizing 모델 도입
5. 그 다음 RL 기반 sizing 또는 exit policy 실험

즉 RL은 나중 단계입니다.

## 6. 필요한 데이터

RL을 제대로 하려면 다음 데이터가 필요합니다.

- OHLCV
- 수수료
- 슬리피지
- 펀딩비
- 호가 스프레드
- 체결 가능 수량
- 주문 지연
- 포지션 상태
- 계좌 잔고 변화

단순 캔들 데이터만으로 RL을 만들면 실전과 괴리가 큽니다.

## 7. 대표 알고리즘

### 7.1 Q-Learning

상태와 행동의 가치를 테이블로 학습합니다. 단순한 문제에 적합합니다.

### 7.2 Deep Q-Network, DQN

Q-learning에 신경망을 붙인 방식입니다.

### 7.3 Policy Gradient

행동 확률 자체를 학습합니다.

### 7.4 Actor-Critic

정책을 담당하는 actor와 가치 평가를 담당하는 critic을 함께 학습합니다.

### 7.5 PPO

Proximal Policy Optimization. 비교적 안정적으로 많이 쓰이는 RL 알고리즘입니다.

## 8. 보상 설계 예시

나쁜 reward:

```text
reward = 이번 거래 PnL
```

이렇게 하면 모델이 과도한 리스크를 선호할 수 있습니다.

더 나은 reward:

```text
reward = realized_pnl
       - fee
       - slippage
       - max_drawdown_penalty
       - position_turnover_penalty
       - liquidation_penalty
```

목표는 단순 수익 극대화가 아니라 위험 조정 수익 극대화입니다.

## 9. 장점

- 복잡한 동적 의사결정 가능
- 진입/청산/사이징을 통합적으로 다룰 수 있음
- 룰로 표현하기 어려운 패턴을 학습할 수 있음
- 시장 regime에 따라 행동을 바꿀 수 있음

## 10. 한계

- 구현 난이도가 매우 높음
- 데이터가 많이 필요함
- 과최적화 위험이 큼
- 실전 체결 환경을 잘 반영해야 함
- 설명 가능성이 낮음
- 수익성 검증이 어렵고 오래 걸림

## 11. 이 프로젝트에서의 현실적 사용법

추천하지 않는 방식:

```text
RL에게 바로 매수/매도를 맡긴다
```

추천하는 방식:

```text
룰 전략이 진입 후보를 만든다.
ML 또는 RL이 신호 품질을 평가한다.
RL은 포지션 크기나 청산 타이밍만 보조한다.
```

## 12. 요약

강화학습은 매력적이지만 자동매매에서 가장 과대평가되기 쉬운 분야입니다.

현재 봇에서는 바로 도입하기보다, 먼저 데이터 저장, 백테스트 현실화, 신호 라벨링, Monte Carlo 리스크 분석을 마친 뒤 제한적인 역할로 도입하는 것이 좋습니다.
